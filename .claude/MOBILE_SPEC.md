# MOBILE_SPEC.md — Tauri 2 Mobile App (iOS + Android)

> **Purpose of this file:** A spec-driven development manifest for Claude Code, adding a **mobile** target that wraps the existing SvelteKit frontend (see `SPEC.md`) using **Tauri 2 mobile**. It lives in its own top-level `mobile/` directory alongside `frontend/`, `backend/`, and `desktop/`. It is **not** Dockerized. Build exactly as described. Values marked `[ASSUMPTION]` are chosen defaults — keep them unless told otherwise. Do **not** rewrite the frontend UI; Tauri reuses it as-is.

---

## 1. Objective

Package the existing Svelte + TypeScript + Tailwind SPA as native **iOS and Android** apps using Tauri 2 mobile. The mobile app:

- Renders the **same** `frontend/` build inside the device's system webview (no UI rewrite).
- Calls the existing FastAPI backend over HTTP.
- Supports hot reloading during development (Vite HMR over the dev server, into the emulator/device).

> **Note:** Tauri 2 targets desktop and mobile from a single project. This spec scopes to **mobile only** in `mobile/`, per the requested directory layout; desktop is a separate spec (`DESKTOP_SPEC.md`). Both reuse `frontend/build` but keep independent Tauri scaffolds. They can be merged into one Tauri project later if you prefer a single native codebase.

| Concern | Choice |
| --- | --- |

## 3. Prerequisites (host machine, not Docker)

Document these in `mobile/README.md`:

- **Rust toolchain** via `rustup`, plus the mobile Rust targets:
  - Android: `aarch64-linux-android`, `armv7-linux-androideabi`, `i686-linux-android`, `x86_64-linux-android`.
  - iOS (macOS only): `aarch64-apple-ios`, `aarch64-apple-ios-sim`, `x86_64-apple-ios`.
- **Node.js 20+**.
- **Android:** Android Studio with SDK + **NDK** + platform tools, and **JDK 17**. Set `ANDROID_HOME` and `NDK_HOME`.
- **iOS (macOS only):** Xcode + Command Line Tools + **CocoaPods**.

The FastAPI backend + Postgres still run via `docker compose up` (see `BACKEND_SPEC.md`). The mobile app talks to that backend over the network — see the addressing rules in §7, which are the crux of making mobile work.

## 5. Shared prerequisite (one-time, idempotent): static frontend build

Same requirement as the desktop spec — apply in `frontend/` **only if not already done**:

1. Switch to **`@sveltejs/adapter-static`** with SPA fallback in `frontend/svelte.config.js`:
   ```js
   import adapter from '@sveltejs/adapter-static';
   export default { kit: { adapter: adapter({ fallback: 'index.html' }) } };
   ```
2. Keep `ssr = false` and `prerender = false` in the root layout (from `SPEC.md`).
3. `npm run build` emits a static SPA to `frontend/build/`.

The Dockerized `npm run dev` workflow is unaffected (the adapter only changes build output).

## 6. Tauri mobile configuration

Scaffold the Tauri project in `mobile/`, then initialize the mobile targets:
- `npm run tauri android init` → generates `src-tauri/gen/android/`.
- `npm run tauri ios init` → generates `src-tauri/gen/apple/` (macOS only).

`src-tauri/tauri.conf.json` (external frontend, same pattern as desktop):

```jsonc
{
  "productName": "CRUD App",
  "version": "0.1.0",
  "identifier": "com.example.crudapp.mobile",   // [ASSUMPTION] change to your reverse-domain id
  "build": {
    "beforeDevCommand": "npm --prefix ../../frontend run dev -- --host",
    "devUrl": "http://localhost:5173",
    "beforeBuildCommand": "npm --prefix ../../frontend run build",
    "frontendDist": "../../frontend/build"
  },
  "app": {
    "security": {
      "csp": "default-src 'self'; connect-src 'self' http://localhost:8080 http://10.0.2.2:8080"
    }
  },
  "bundle": { "active": true, "targets": "all" }
}
```

- `lib.rs` must expose the `run()` function with `#[cfg_attr(mobile, tauri::mobile_entry_point)]` — this is the mobile entry point and is **required** for mobile builds (standard scaffold; no custom Rust needed).
- On mobile dev, Tauri serves the frontend dev server and injects a device-reachable dev URL into the webview automatically, so `--host` on the Vite dev server is required (bind `0.0.0.0`).

`[ASSUMPTION]` App name "CRUD App", bundle id `com.example.crudapp.mobile` — change freely.

## 7. Backend addressing (the critical part for mobile)

On a phone/emulator, `localhost` means the **device itself**, not your dev machine — so `http://localhost:8080` will **not** reach the backend. The frontend reads `VITE_API_BASE_URL` at build time, so build the frontend with a **device-reachable** address for the target:

| Target | `VITE_API_BASE_URL` |
| --- | --- |
| Android emulator | `http://10.0.2.2:8080` (special alias for the host's localhost) |
| iOS simulator | `http://localhost:8080` (simulator shares the host network) |
| Physical device (either OS) | `http://<your-dev-machine-LAN-IP>:8080` (e.g. `http://192.168.1.20:8080`); device and machine on the same network |

Set `VITE_API_BASE_URL` in the environment before the frontend build that Tauri bundles (i.e. before `beforeBuildCommand` runs, or via an `.env` in `frontend/`). Document the three cases in `mobile/README.md`.

### 7.1 Cleartext HTTP in development

The dev backend is plain `http://` (no TLS), which mobile OSes block by default. For **development only**, allow it:

- **Android:** enable cleartext for the backend host via a network security config referenced from the generated `AndroidManifest.xml` (`android:networkSecurityConfig`), or `android:usesCleartextTraffic="true"` in the `gen/android/` project. Scope it to the dev host if possible.
- **iOS:** add an App Transport Security (ATS) exception in the generated `Info.plist` (`NSAppTransportSecurity` → `NSAllowsLocalNetworking` / a per-domain exception) for the dev host.

Remove these exceptions before shipping a production build over TLS.

### 7.2 CORS

Add the mobile webview origins to the backend `CORS_ORIGINS` (per `BACKEND_SPEC.md`):
- Android: `https://tauri.localhost`
- iOS: `tauri://localhost`
- Dev server origin `http://localhost:5173` is already allowed.

**Alternative (optional, recommended if CORS/cleartext proves fiddly):** use `@tauri-apps/plugin-http` so requests are issued from Tauri's native Rust HTTP client, which bypasses both webview CORS and webview cleartext restrictions (you'd still set the correct base-URL address from §7). This couples the frontend to a Tauri dependency, so it's optional; if used, gate it behind a Tauri runtime check in `client.ts` and allowlist the backend URL in `capabilities/default.json`.

## 8. Development & build

**Dev (with hot reload):**
1. Start backend + DB: `docker compose up backend db`.
2. From `mobile/`, run a target:
   - Android: `npm run tauri android dev` (boots an emulator or attached device).
   - iOS: `npm run tauri ios dev` (boots a simulator or device; macOS only).
   Tauri runs `beforeDevCommand` (Vite dev server with `--host`) and loads it in the device webview; editing `frontend/src` hot-reloads inside the app.
3. Ensure `VITE_API_BASE_URL` matches the target per §7, and the dev cleartext exceptions (§7.1) are in place.

**Production build / bundle:**
- Android: `npm run tauri android build` → APK/AAB under `src-tauri/gen/android/`.
- iOS: `npm run tauri ios build` → `.ipa` / Xcode archive under `src-tauri/gen/apple/` (macOS only; signing required for devices).

## 9. Build order (do this sequentially)

1. Apply the shared static-frontend change in §5 (skip if already done by the desktop spec).
2. Scaffold the Tauri 2 project in `mobile/`, pointing `frontendDist`/`devUrl` at `frontend/` (§6).
3. Ensure `lib.rs` has the `#[cfg_attr(mobile, tauri::mobile_entry_point)]` `run()` entry point.
4. Run `tauri android init` and (on macOS) `tauri ios init` to generate the native projects.
5. Configure backend addressing: set `VITE_API_BASE_URL` per target (§7), add dev cleartext exceptions (§7.1), add mobile CORS origins to the backend (§7.2).
6. Write `mobile/README.md` with prerequisites (§3), the addressing table (§7), and run steps (§8).
7. Verify dev: backend/db up, `tauri android dev` (and/or `ios dev`) launches the app doing full CRUD with hot reload against the correct base URL.
8. Verify build: produce a debug APK / simulator build that performs CRUD against the running backend.

## 10. Definition of done (acceptance criteria)

- [ ] `mobile/` is a self-contained Tauri 2 mobile project; the frontend UI is reused unchanged (no Svelte rewrite).
- [ ] The frontend builds to static assets via `adapter-static`; the Dockerized dev workflow still works.
- [ ] `tauri android dev` (and `tauri ios dev` on macOS) launches the app on an emulator/simulator with hot reload on `frontend/src` edits.
- [ ] The app reaches the backend using the correct per-target address (Android emulator `10.0.2.2`, iOS simulator `localhost`, physical device LAN IP) and performs full CRUD.
- [ ] Dev cleartext-HTTP exceptions are configured for Android and iOS; mobile CORS origins are allowed on the backend.
- [ ] Debug builds/bundles are produced for Android (and iOS on macOS).
- [ ] Nothing in `mobile/` is Dockerized; prerequisites and addressing are documented in `mobile/README.md`.
- [ ] No frontend UI changes; no backend changes beyond CORS origins (and optional plugin allowlist).
